Stdlib-only helper scripts. Every script reads `.pai-harness.toml` through `harness_config.py` (`--config`, `PAI_HARNESS_CONFIG`, or the nearest file upward) and has `--dry-run`.

- `validate_config.py`, `load_config.py`: the config validator and loader.
- `agent-start.sh <name> --role R --parent P --pane X [--issue I] [--kind K] -- <agent args>`: `herdr agent start` plus `pai-pane-meta` (name, role, parent, issue, and `wake_on_done=1` for one-shot roles only: implementer, reviewer, answerer, gate, verifier, mechanical; leads, orchestrators and relays live across turns and would wake their parent on every turn end; `--wake` / `--no-wake` override) in one step. **Enforced by the script:** name/role match `[a-z][a-z0-9_-]{0,31}` and parent/pane/issue a safe charset (else exit 2, nothing tagged); `jq` is required; tags are set in strict mode and verified on the pane (by pane id) after the start, so a missing name/role/parent/wake_on_done exits 1 (`FAILED <name>`). If `herdr agent start` exits non-zero but the agent is running (`agent_not_ready`), it is tagged anyway and the script exits 3 (`STARTED-NOT-READY`): do not start it again, read it and wait for idle. Works through a symlink. Agent args pass through unchanged; the permission default lives in `launch.py`. **Convention, not enforced:** that every interactive agent is started through it (a bare `herdr agent start` still works and is untagged; `health.sh check` warns about the harness agents it can see).
- `launch.sh`: one issue as `claude -p --output-format stream-json --verbose`, alone or in a Herdr pane. Writes the stream to `runs/<ISSUE>.jsonl` and the verdict (state, cost, turns, session id, exit code) to `runs/<ISSUE>.state.json`. State comes only from the `result` frame and the exit code. Runs pass `--permission-mode bypassPermissions` unless `[run] bypass_permissions = false`, and refuse (blocked, exit 3) unless the deny baseline is in the effective Claude Code settings (the waiver is the user-level policy file only; see `../examples/README.md`). Exit 0 done, 1 failed, 2 usage, 3 blocked on a permission or the deny baseline. Also `--status`, `--park`, `--resume`. In a pane it tags the pane with the pai wake tokens before the run (name = lower-cased issue id, role, parent, issue, `wake_on_done=1`) and fails closed: no parent (`--parent P` or `PAI_HARNESS_PARENT`; `--no-parent` opts out) or an invalid name/role exits 2, a failed tag exits 1, and a pane the wake cache shows hosting another agent is refused; the run does not start. `dispatcher.sh` passes its `PAI_HARNESS_PARENT` as `--parent`. `health.sh check` warns about harness agent panes missing wake tokens.
- `launch.sh ISSUE --profile mechanical --files F... --instruction TEXT`: the mechanical lane. Closed brief, Haiku (`--model sonnet` opts in), `--strict-mcp-config` with an empty MCP config, `--tools`/`--allowed-tools` Read, Edit, Grep, Glob, `--max-turns 12` and `--max-budget-usd 0.25` (override with `[role_limits.mechanical]`), `--output-format json`. Needs a clean git worktree (`--cwd` may be a repository subdirectory: `--files` are relative to it and recorded repo-root-relative); records `profile`, `files`, `base`, `cwd`, `root` and a baseline of the gitignored files for the verifier. The child gets an allowlisted environment (PATH, HOME, locale, Claude sign-in variables; more names via `PAI_HARNESS_LANE_ENV`), no Pai/SSH/cloud credentials, and no `PAI_HARNESS_ROLE`: the plugin hooks do nothing in the lane (it has no Write or MCP to satisfy the Stop delta marker or zones) and the verifier is its guard. The command passes `--restricted` (ignores user, project and local settings, confines the file tools to the run directory, refuses `bypassPermissions`; needs a claude that has it) and `--permission-mode dontAsk`, with allow rules for `Read`/`Edit`/`Grep`/`Glob` under the run directory only. Deny rules add, in depth: `Edit` on `.git` (repo and common dir), `.claude`, `.mcp.json`, the harness state dir and dependency/cache directories at any depth (`**/node_modules/**` ...), and `Read` on the state dir, the token file, `.git` and the usual credential locations. Checked against the installed claude (`PAI_HARNESS_LIVE_CLAUDE=1` runs that test). The verifier also hashes git config, hooks and attributes at launch and fails closed if the lane or a check changed them. Proxy, CA and (when selected) Bedrock/Vertex variables pass; `PAI_HARNESS_LANE_ENV` accepts only a short safe list (CI, NO_COLOR, ...) unless `PAI_HARNESS_LANE_ENV_ALLOW_SECRETS=1`; provider flags count as on only for 1/true/yes/on. `--files` entries are literal paths (`[slug]` is fine; `*`, `?` and control characters are refused).
- `verify-mechanical.sh ISSUE (--check CMD | --gate NAME)...`: passes a mechanical run only if it is `done`, the diff (tracked, staged, untracked and gitignored-since-launch) touches only the listed files and every check passes; the scope is measured again after the checks (tolerant: the checks may write caches and build output; only tracked/untracked paths, the listed files and sensitive ignored names like `.env` or `*.pem` count). Every git call runs with fsmonitor, hooks and pager of the repo config disabled. Otherwise restores the changed paths (`--keep` to leave them) and exits 1. Fails closed: a git failure or timeout writes a `discard` verdict (replacing any earlier pass) and a `BLOCKER`. `--dry-run` never prints `pass` (verdict `unverified`, exit 1). Marks every 5th passing run (a persistent counter in the state dir, one slot per run; `--sample-every` 1 to 5 can only add runs) for a Sonnet review. Run it before committing the work.
- `task-done.sh`: closes only a `done` run, and prints the three-line status. A mechanical run also needs a passing verify verdict that still matches the tree (same changed content; committing the verified work is fine, HEAD must stay a descendant of the start commit), and, when sampled, `--sample-reviewed REVIEW_FILE`: JSON with `reviewer`, `verdict: clean` and the `diff_sha256` of the verify verdict.
- `health.sh`: `beat NAME` and `check`; a running entry is stale after 15 minutes (exit 1; 2 for an empty registry). `check` also warns (`untagged-agent-pane`, exit code unchanged) about harness agent panes missing any of name/role/parent (and wake_on_done for a one-shot role). Scope: agents carrying at least one pai token or named like a registry entry; other Herdr agents are not checked. Herdr binary: `HERDR_BIN_PATH`, else `PAI_HARNESS_HERDR`. The probe runs only when the registry is not empty. `check` also verifies the deny baseline of this machine and ends with a named `FAIL deny-baseline` and exit 4 when bypass agents may run and the rules are missing (skipped in the Codex package).
- `deny_baseline.py --check [--cwd DIR] [--role ROLE] [--strict]`: the standalone deny-baseline check (exit 0 present, 1 missing, with the settings files it read and the missing rules). Run it as step 0 on every machine that runs bypass agents, before starting them; an interactive agent start never goes through `launch.sh`.
- `dispatcher.sh`: reads ready lines, honours queue, machine and global limits, launches at most that many.
- `gate-request.sh`: asks `[gates]` for one full 40-character sha; `--run` runs them; `--root` reports ROOT hits.
- `linear-status.sh`: the Done/Next/Blocked comment; posts only when the token env var (`LINEAR_API_KEY`) and `LINEAR_API_URL` are both set.

State dir: `PAI_HARNESS_STATE_DIR`, else `$XDG_STATE_HOME/pai-harness/<pai_project>` (never a temporary directory). Registry entries live in `registry/`, events go through the command in `PAI_HARNESS_MCP_CMD` (one JSON object on stdin) when it is set and works, and otherwise append to `journal.jsonl`. `PAI_HARNESS_CLAUDE` and `PAI_HARNESS_HERDR` override the binaries (tests use fakes).

## Which lane

| Work | Use |
|---|---|
| Fully deterministic (a regex rename, a formatter, a codemod) | a script; no model |
| The same small edit across known files, with a little reading (rename `calc_total` in `src/cart.py` and `src/totals.py`) | the mechanical lane: `launch.sh ACME-12 --profile mechanical ...`, then `verify-mechanical.sh` |
| Issues, reviews, decisions, anything that needs a command, the network, Pai tools or scope judgment | an interactive session |
