Stdlib-only helper scripts. Every script reads `.pai-harness.toml` through `harness_config.py` (`--config`, `PAI_HARNESS_CONFIG`, or the nearest file upward) and has `--dry-run`.

- `validate_config.py`, `load_config.py`: the config validator and loader.
- `agent-start.sh <name> --role R --parent P --pane X [--issue I] [--kind K] -- <agent args>`: `herdr agent start` plus `pai-pane-meta` (name, role, parent, issue, `wake_on_done=1`) in one step. **Enforced by the script:** name/role match `[a-z][a-z0-9_-]{0,31}` and parent/pane/issue a safe charset (else exit 2, nothing tagged); `jq` is required; tags are set in strict mode and verified on the pane (by pane id) after the start, so a missing name/role/parent/wake_on_done exits 1 (`FAILED <name>`). If `herdr agent start` exits non-zero but the agent is running (`agent_not_ready`), it is tagged anyway and the script exits 3 (`STARTED-NOT-READY`): do not start it again, read it and wait for idle. Works through a symlink. Agent args pass through unchanged; the permission default lives in `launch.py`. **Convention, not enforced:** that every interactive agent is started through it (a bare `herdr agent start` still works and is untagged; `health.sh check` warns about the harness agents it can see).
- `launch.sh`: one issue as `claude -p --output-format stream-json --verbose`, alone or in a Herdr pane. Writes the stream to `runs/<ISSUE>.jsonl` and the verdict (state, cost, turns, session id, exit code) to `runs/<ISSUE>.state.json`. State comes only from the `result` frame and the exit code. Exit 0 done, 1 failed, 2 usage, 3 blocked on a permission. Also `--status`, `--park`, `--resume`. In a pane it tags the pane with the pai wake tokens before the run (name = lower-cased issue id, role, parent, issue, `wake_on_done=1`) and fails closed: no parent (`--parent P` or `PAI_HARNESS_PARENT`; `--no-parent` opts out) or an invalid name/role exits 2, a failed tag exits 1, and a pane the wake cache shows hosting another agent is refused; the run does not start. `dispatcher.sh` passes its `PAI_HARNESS_PARENT` as `--parent`. `health.sh check` warns about harness agent panes missing wake tokens.
- `task-done.sh`: closes only a `done` run, and prints the three-line status.
- `health.sh`: `beat NAME` and `check`; a running entry is stale after 15 minutes (exit 1; 2 for an empty registry). `check` also warns (`untagged-agent-pane`, exit code unchanged) about harness agent panes missing any of name/role/parent/wake_on_done. Scope: agents carrying at least one pai token or named like a registry entry; other Herdr agents are not checked. Herdr binary: `HERDR_BIN_PATH`, else `PAI_HARNESS_HERDR`. The probe runs only when the registry is not empty.
- `dispatcher.sh`: reads ready lines, honours queue, machine and global limits, launches at most that many.
- `gate-request.sh`: asks `[gates]` for one full 40-character sha; `--run` runs them; `--root` reports ROOT hits.
- `linear-status.sh`: the Done/Next/Blocked comment; posts only when the token env var (`LINEAR_API_KEY`) and `LINEAR_API_URL` are both set.

State dir: `PAI_HARNESS_STATE_DIR`, else `$XDG_STATE_HOME/pai-harness/<pai_project>` (never a temporary directory). Registry entries live in `registry/`, events go through the command in `PAI_HARNESS_MCP_CMD` (one JSON object on stdin) when it is set and works, and otherwise append to `journal.jsonl`. `PAI_HARNESS_CLAUDE` and `PAI_HARNESS_HERDR` override the binaries (tests use fakes).
