Hooks of the harness. They run only when `PAI_HARNESS_ROLE` is set; without it every hook does nothing.

| Event | Script | What it does |
| --- | --- | --- |
| SessionStart | `session_start.py` | Prints the brief (`PAI_HARNESS_BRIEF`) and the curated Knowledge as `additionalContext`. Knowledge comes from the command in `PAI_HARNESS_KNOWLEDGE_CMD`, which reads one JSON object (`role`, `agent`, `session_id`, `project`) on stdin and prints markdown. |
| Stop | `stop.py` | Blocks stopping while the worktree holds changes outside the agent's zones (`zone_diff.py`, see below), and until `<state dir>/deltas/<agent>.json` holds `{"nodes": [...]}` with at least one node reference. The agent is `PAI_HARNESS_AGENT`, else the session id. The block is bounded: after 3 blocks (counted in `deltas/<agent>.blocks`) the next stop is allowed and `deltas/<agent>.missing` is written next to the delta marker, so a `claude -p` run never loops. A valid delta clears both files. |
| PreToolUse | `pre_tool_use.py` | Denies a Write, Edit, MultiEdit, NotebookEdit or Bash redirect/`tee` outside the role's zones, naming the zone owner, and denies every push that does not go through the push queue wrapper, and every push with `--no-verify`. |

Zones come from `.pai-harness.toml`. The agent's zones are the names in `PAI_HARNESS_ZONES` (comma separated), else the zones that list `PAI_HARNESS_AGENT` as an owner. Paths outside the project root and the state dir are not policed. A push is allowed only when the command starts with the push queue wrapper (`rules.push_wrapper`, else `PAI_HARNESS_PUSH_WRAPPER`). Every spelling of a direct push is refused: `/usr/bin/git push`, `git -C DIR push`, `env X=1 git push`, `command git push` (also `exec`, `nohup`, `sudo`, `nice`, `timeout`), `bash -c` and `eval`, `git -c alias.x=push x`, and any git alias that resolves to push (read from `git config`, including shell aliases such as `!git push`). A push with `--no-verify` (or an abbreviation of it) or a `core.hooksPath` override is refused even through the wrapper. With a role set and no usable config, writes and pushes are denied; Stop and SessionStart do nothing.

The launcher (`scripts/launch.py`) exports `PAI_HARNESS_ROLE`, `_AGENT` (the issue), `_ZONES` (from `[role_zones]`; an unmapped role falls back to zone owners), `_BRIEF`, `_PUSH_WRAPPER` (`rules.push_wrapper`), `_CONFIG` and `_STATE_DIR` to the run. `PAI_HARNESS_KNOWLEDGE_CMD` is site tooling with no config key, so an operator's value passes through the inherited environment.

**Stop-time zone diff (`zone_diff.py`):** PreToolUse sees the Write tools, redirects and `tee` only; it cannot see a `sed -i`, `cp`, `mv` or a python or node script that writes a file. So at Stop the hook reads the changed paths from git (`git status --porcelain` with untracked files, plus `git diff --name-only` against the base commit) and runs each through the same zone check as PreToolUse. The base commit is `PAI_HARNESS_BASE`, else the merge-base of HEAD with `origin/HEAD`, `origin/main`, `origin/master`, `main` or `master`. Any changed path outside the agent's zones blocks the stop and names the zone owner; the state dir and paths outside the project are not flagged. A project that is not a git repository flags nothing. The block shares the delta bound: after 3 blocks the stop is allowed and `deltas/<agent>.missing` also lists the `out_of_zone` paths. A clean worktree clears the count and the marker.

**Zoneless writing roles:** a writing role (`WRITING_ROLES` in `scripts/harness_lib.py`: implementer, mechanical, integrator) with no zone assigned would pass the diff unchecked, so Stop blocks it with "no write zone configured for ROLE; ask your lead", inside the same 3-block bound (the `.missing` marker then names this problem). Non-writing roles (relay, orchestrator, lead, watcher, root-reviewer, gate-triager, distiller) may run zoneless. The launcher also refuses to start a writing role outside a git worktree (`git rev-parse --is-inside-work-tree` on the run's cwd): it prints a `BLOCKER` line, journals a `run.blocked` event and exits 1. Tests: `tests.test_harness_writing_roles`.

Remaining limits: the diff runs once, at Stop, so an out-of-zone write is caught at the end of the session and not when it happens; a file changed outside the project root, or ignored by git, is not seen. Command substitution and variables used as a command name are not resolved in Bash commands either (a first word containing `$` with `push` as an argument is refused as a precaution).

The hooks only allow or deny; they never ask. Tests: `python3 -m unittest tests.test_harness_hooks tests.test_harness_zone_diff`.

## Git guardrails

`git_guardrails.py` is called once from `pre_tool_use.py` for every Bash command of an agent with a role. It denies force, delete, mirror and prune pushes, and pushes to main, staging, production or release/* (all through the push queue wrapper), `git reset --hard`, `git clean`, `git branch -D`, `git stash drop`, `git rebase -i`, `git update-ref -d`, `git worktree remove --force`, `git checkout .` / `git restore .` and `rm -rf .git`. Each denial names the command and a safe alternative. A PreToolUse deny is expected to hold in bypass-permissions mode too; this is verified only with simulated hook runs (`permission_mode: bypassPermissions` in the hook input), not against an installed client session.

Opt-in for a throwaway path: set `PAI_HARNESS_GIT_THROWAWAY` to relative paths of the agent's own git top level (separated by `,` or `:`). Only `checkout`/`restore` of a broad pathspec and `git clean` can be opted in, and only for targets inside those paths. Code generated at run time (`python -c`, `base64 -d | sh`) is not read.

Protected branches default to main, staging, production and release/*. Set `PAI_HARNESS_PROTECTED_BRANCHES` (globs separated by `,` or `:`) in the launcher environment to replace the list for a role; an unset, empty or separator-only value keeps the default list, so protection cannot be switched off by a template that renders an empty string. The wrapper push is read in both forms (`wrapper origin REF` and `wrapper git push ...`); `--all`, `--branches`, a glob destination, `@` and a bare `HEAD` are resolved fail-closed: `cd` is followed, and a directory or branch that cannot be read in time (or at all) denies. Git lookups are cached per command and bounded to 5 s in total. `--no-verify` and `core.hooksPath` are left to `pre_tool_use.py` (`analyze()`), which matches them case-insensitively. A shell fed from a pipe that names the wrapper is refused. With `push.default=upstream`, a bare `wrapper git push` is checked against the current branch name, not the upstream name.

Further rules: the wrapper is recognised by file identity, so `./scripts/q.sh` and an absolute path count as the wrapper; a refspec built at run time (`$B`, `$(...)`, backticks, `~`) is refused; a detached HEAD or a missing directory denies a bare-HEAD push with its own message; an internal error or an unparseable wrapper value denies instead of raising (a hook that raises does not block). Also blocked: `git switch -f/--discard-changes/-C`, `checkout -B`, `filter-branch`, `reflog expire/delete`, `gc --prune=now`, `tag -d`, `remote rm`. Not blocked on purpose: `reset --merge/--keep` (they refuse to lose changes) and `remote prune` / `fetch --prune` (they only drop stale tracking refs). Shells with combined flags (`bash -lc`) are read like `bash -c`.
