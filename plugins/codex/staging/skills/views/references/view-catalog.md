> Generated by `tools/gen-references.ts` from pai-portal `22a3e214f` (archived contract snapshot), `packages/views/src/catalog.ts`. Do not edit manually: regenerate.

Format: Flat json-render spec: { root: id, elements: { [id]: { type, props, children?, slots? } } }. Children are referenced by id.

## Rules

- Use only components in this catalog; no className, style, colors, or HTML.
- Each props object is closed: only its schema's props are allowed; all others are rejected.
- IDs are unique, start with a letter, and are reused when editing.
- Omitted props that accept null use their default value.
- Only AppShell, AuthFrame, ConsoleShell, PortalShell, SiteShell, ContactSection, AuthLayout, BoardLayout, ChatLayout, DashboardLayout, DetailLayout, DocLayout, EmptyLayout, FilesLayout, FormLayout, PageLayout, SettingsLayout, SplitView, WizardLayout, Card, Collapsible, DetailSheet, DialogFrame, Frame, Grid, Section, Stack, Tabs, UnderlinedTabs, Tooltip, ButtonGroup, Popover, Scrollspy, Stepper, and ProposalSummary have children; Tabs and UnderlinedTabs have one child per tab, in order.
- Components with slots (Card, Item, ChatComposer) contain elements in slots: { nombre: [ids] }, like children (one parent, connected to the root), and only of the types allowed by each slot (listed in its detail).
- Choose layout through the view root: AppShell, AuthFrame, ConsoleShell, PortalShell, SiteShell are complete screens (see layouts) and belong only at the root; a document, report, or dashboard starts with Stack. Never recreate a Pai screen with AppShell: AppShell is for client apps.
- Before using a component, request its description, schema, and example with view_catalog({ types: [...] }) or by group (view_catalog({ group })); only its summary is included here and, in groups with index props, its props by name (nombre? means optional). Groups with index names provide only summaries: request their props by group.
- A pattern (patterns group) has one child per region, in region order; regions selects which regions to use, in that same order.
- For a full screen, you may start from a recipe (recipes, by group): view_catalog({ recipeGroup }) returns a group's summaries and view_catalog({ recipe }) the complete view, which you adapt with your data. This is optional.
- Static data: supply already formatted values, with their as-of date in the detail or description.
- Links only to Portal paths (/…) or https.
- Maximum 300 elements and 12 nesting levels.

## Layouts: the view root

A full screen uses one of these components as `root` (only there). A document, report or dashboard starts with `Stack`.

- **AppShell**: Client app: sidebar with menu and user, header, and content. Root only.
- **AuthFrame**: Pai identity screen (login, registration, invitation) with its card. Root only.
- **ConsoleShell**: Console screen identical to the real one: menu, breadcrumbs, and title. Root only.
- **PortalShell**: Portal screen identical to the real one: organization selector, area menu, and breadcrumbs. Root only.
- **SiteShell**: pai.lat page with header, footer, and cookies; children are site sections. Root only.
- **Stack**: Document, report, or dashboard within a Resources page (without app chrome).
