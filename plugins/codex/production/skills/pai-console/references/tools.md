## Image content: `asset_read` and `assets`

`page_read` (every `view`), `whiteboard_read` and `knowledge_get` return `assets`: the assets their content uses that the reader can see, always present (`[]` when none). Each entry has `id`, `filename`, `kind` (`image`, `video`), `mimeType`, `width`, `height` (null when unknown), `sizeBytes`, `alt` (from the content; null on whiteboards) and `readable` (true for images: `asset_read` answers them).

`asset_read {organizationId, projectId, assetId, size?}` returns the image itself as MCP `image` content, preceded by a text line, plus `structuredContent {asset: {id, filename, contentType, width, height, sizeBytes}, image: {mimeType, width, height, bytes, transform, animated}}`; the base64 is only in the `image` block.

| Limit | Value |
|---|---|
| `size: "standard"` (default) | long side ≤ 1568 px, ≤ 1,200,000 pixels |
| `size: "thumbnail"` | long side ≤ 512 px |
| Encoded output | ≤ 1,000,000 bytes, as `image/png`, `image/jpeg`, `image/webp` |
| Decoded input | ≤ 40,000,000 pixels |
| Read and render time | 10 s |

`transform` is one of `original`, `resized`, `reencoded`, `rasterized`, `first_frame`: a fitting PNG/JPEG/WebP is sent unchanged, a larger one is reduced, a GIF gives its first frame (`animated: true` when it had more) and an SVG is rasterized. Errors: `not_found` (missing, hidden, pending or another project's asset, indistinguishable), `unprocessable` with reason `ASSET_NOT_IMAGE`, `ASSET_IMAGE_TOO_LARGE`, `ASSET_IMAGE_UNREADABLE` or `ASSET_SVG_REFUSED`, `timeout` `ASSET_READ_TIMEOUT`, `unavailable` `STORAGE_UNAVAILABLE`.

Client-only proposal_accept/proposal_reject are not staff tools. Do not substitute a client credential or change memberships to bypass actor or resource restrictions.
