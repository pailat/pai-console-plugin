## Catalog rules

- IDs are unique across the entire page.
- Markdown text and literal HTML; no JavaScript execution.
- Maps express a question, propositions, evidence and limits without duplicating prose.
- Quizzes test taught distinctions; results guide review, not certification.
- Reader answers are not part of the document.
- Images/videos are project assets: asset_list to reuse, asset_upload + PUT + asset_confirm to upload. Store assetId (figure/video) or /api/pages/assets/{assetId}. The service checks project ownership, readiness and visibility.
- Interactive HTML uses an html block {id, type: html, title, description?, html, height}. Portal renders an isolated iframe without cookies, storage or network. HTML may be a document or fragment, ≤512 KB per block and ≤1 MB per page; height is auto or 120..4000px. Scripts must be inline or from html.scriptSources; no fetch/XHR (connect-src none). Embed data and use Pai CSS tokens for light/dark mode. Never put an HTML preview fence in Markdown.
- Whiteboard block {id, type: whiteboard, page, title?}: page is the same-project whiteboard page id, created using whiteboard_create. Renders a preview with Open and, for editors, Edit here. Client pages embed only client-visible boards.
- Flow block {id, type: flow, node, title?, height?}: node is a same-project Knowledge flow id; height is 240..1200px, default 480. Renders read-only with Open. Client pages embed only client-visible flows.
- API designs: to show the reference of a project API design use an api block {id, type: api, apiDesignRef, revision?}; apiDesignRef is the design id (api_design_list) and revision pins the one shown (without it, the current one). It draws the reference read-only, never a copy of the document; someone who cannot see the design, such as a client with a staff-only one, sees «No disponible».
- Embeds store HTTPS links only (Figma, Google Slides, Miro, YouTube, Loom or other sites), never HTML or iframe code.
- Figures use assetId null until the file exists; never invent an assetId or link an external image.
- Declare sources once in a sources block with URL and ISO date. facts, data-table, quote and figure cite sourceRef.
- Store figures in facts/data-table with cutoff dates; do not repeat unsupported amounts in prose.
- Deliverables reference requirements by id. A requirement must have acceptance criteria.
- Dashboards/visual reports/free pages use view blocks, sized automatically. Compose specs from views.groups and validate with page_validate. Built-in types do not allow view: omit typeSlug or select a custom organization/project type allowing it.
- Knowledge (schemaVersion 2): a block cites nodes from the project or its organization with refs [{nodeId, revision, role}] (role cites, grounds or subject), or inline with [text](kb:kind/slug@rN) or <kb:kind/slug@rN> in text, callout, cards and comparison (never inside backticks or HTML: KNOWLEDGE_CITATION_OUTSIDE_LINK); on save, the server adds each inline citation to the block refs (without @rN it uses the current revision). A client page (audience client) only cites client-visible nodes: page_validate lists them.
- Projections (schemaVersion 2) render existing Knowledge instead of copying data: {id, type: projection, format, selection, params?, title?, caption?}. Formats cover C4/ERD/screens/use cases/flows/decisions/requirements/risks/glossary. No own data is stored; reads respect reader visibility. format comes from projection.formats; selection is {refs: [{nodeId, revision}]} or {query: KnowledgeQuery}, as supported; kinds and params must match the format schema. caption is one Markdown line without kb citations. Validate before save; client pages project only client-visible nodes.

## Blocks

- `text`: Markdown headings, lists, tables, links and literal code.
- `callout`: Context, warning or conclusion in Markdown.
- `steps`: Actions with titles and descriptions.
- `cards`: Concepts in two, three or four columns.
- `comparison`: Alternatives in Markdown.
- `timeline`: Dates, events and their meaning.
- `glossary`: Expandable terms and definitions.
- `mermaid`: Restricted Mermaid with text alternative and no callbacks.
- `relationships`: Positioned entities/connections with evidence, exploration and accessible list.
- `quiz`: Questions, options, correct answers, explanations and review links.
- `facts`: Figures/metrics with unit, cutoff, trend and cited source.
- `requirements`: Statement, priority, rationale and acceptance criteria.
- `sources`: Citable title, URL, type, publisher and retrieval date.
- `figure`: Project image assetId, alt text, caption and credit.
- `video`: Project MP4/WebM with player, caption and optional poster.
- `embed`: HTTPS iframe/link for Figma, Google Slides, Miro, YouTube, Loom or another site, with title/caption.
- `data-table`: Declared columns, positional rows, note and cited source.
- `quote`: Verbatim statement with attribution, role, context and cited source.
- `risks`: Probability, impact, mitigation, owner and status.
- `deliverables`: Acceptance criteria, owner, date and requirements.
- `view`: Free view composed from pai-view@1 layouts/metrics/charts/tables/tabs; its spec is documented in views.
- `html`: HTML/JS mockup in an isolated fullscreen-capable iframe.
- `whiteboard`: Project whiteboard id with preview, Open and editor-only Edit here.
- `flow`: Project Knowledge flow id with read-only canvas and Open.
